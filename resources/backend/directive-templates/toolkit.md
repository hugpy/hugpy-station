## Station toolkit — what exists, when to use it, the exact call
{{toolkit_focus}}
Tools are `mcp__toolserver__<name>`; `ts_categories`, then `ts_list {category}`, give the exact parameters. Docs: `{{docs}}/`.
- **Board = the worklist** (🧭 d4189): every task you discuss goes on the board. Close an item with a note that names what shipped and how you checked it. `todo_list {status, type, locus:"{{locus}}"}` · `todo_batch {locus:"{{locus}}", by:"{{signature}}", ops:[{op:"add"|"update"|"done", …}]}` (`ops` is a LIST, at most 50 per call) → `TODO-BOARD-SOP.md`.
  - Tabs: queue = `todo` (yours) + `request` (asked of you) · ⚑ operator = commands only the operator can run · ⚖ proposals = a decision for the operator · 🔖 bookmarks = checkpoints and references to return to · 🧭 directions = operator rulings that carry a `DERIVE:` hint and are closed once folded into a doc or template.
  - Operator items and proposals: the shape is in "Board items" above (`BOARD-ITEM-FORMAT.md`). Fix the sections a refusal names and write the item again.
- **Conversation or action, to a peer locus:** `comms_ping {to, kind:"message", text, from_:"{{signature}}"}` for acks, findings and questions (it drains to the peer's ✉ tab). Use `kind:"request"` only for an action the peer must take. Read yours with `comms_inbox {to:"{{locus}}"}` → `STATION-TOOLS.md` (comms).
- **A prompt into a locus's keeper session:** `POST http://127.0.0.1:{{station_port}}/api/prompt/send?vm=<locus> {"text", "target":"auto"}`. Read `state`: `delivered`, `queued` (busy; it will run next) or `failed` (NOT delivered: report it, never assume it arrived).
- **This locus's standing sessions:** `session_message {to: keeper|chat|worker|local, text}`. **Bug reports** (findings, loops, tracebacks) go to the WORKER session only, never the keeper (🧭 d4188). Never type into another account's tmux. Cross-account work goes by comms, a prompt or the board.
- **B (local, free):** delegate search, reading, triage and summaries to it (`session_message {to:"local"}` or `POST /api/b/chat {"text"}`). B annotates and suggests. It is NOT a gate and gives no verdict: nothing it says may drop or hide a ping (🧭 d4187).
- **Subagents:** use them for parallel or bulky work. Isolate their edits in a git worktree under `{{home}}/tmp/<name>` (not `/tmp`, which is wiped at boot). Ask for short reports: `file:line`, evidence paths, and the command plus the tail of its output.
- **Toolserver categories worth knowing:** `issue_*` (observe and annotate, never suppress: `issue_list`, `issue_get`, `issue_observe`) · `exchange_*` (the conversation record: `exchange_list {locus}`) · `fs_*` for search on the toolserver's host (`fs_search`, `fs_find_content`, `fs_read_span`) · `db_*` read-only (`db_query`, SELECT/WITH only) · `vm_*` / `vmpool_*` (`vm_hosts_overview`) · `image_*` / `media_*` · `metrics_*` · `instructions_read` (operating guides).
- **Docs, by task:** item shape → `BOARD-ITEM-FORMAT.md` · board lanes and lifecycle → `TODO-BOARD-SOP.md` · tool parameters → `STATION-TOOLS.md` (short form: `STATION-TOOLS-DIGEST.md`) · what this locus has → `STATION-FEATURES-PER-LOCUS.md` · words → `NOMENCLATURE.md`.
